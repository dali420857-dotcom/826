# Dali Outreach phase-0 threat model

Status: verified for local synthetic/fake/no-send runtime; provider/live remains blocked and unverified.

The phase-0 boundary is a local, synthetic, monitoring-only assembly containing Email and Telegram. Loopback is not treated as authentication. A bridge request must pass exact Host and Origin checks, a per-process capability check, a server-side role check, strict schema validation, and the operation allowlist generated by the installed modules.

Hard invariants:

- Active/live modes and every provider adapter are rejected even when credentials exist in the environment.
- Outbound non-loopback network access fails closed during tests and local phase-0 execution.
- Approval binds the content hash, template version, variables version, target-set hash, and expected state version. Any edit invalidates it.
- Unknown state-changing outcomes require reconciliation before retry.
- Inputs have explicit size and row caps. CSV cells are protected against formula injection and paths cannot escape the import boundary. Email HTML is sanitized; Telegram MarkdownV2, links, and control characters are escaped.
- Logs, errors, fixtures, and screenshots contain only synthetic or masked data and never expose stack traces, bodies, credentials, tokens, or session material.
- There is no arbitrary URL, shell, SQL, filesystem-write, or generic method bridge.

Rollback uses the activation manifest. It disables the new entry while preserving source and audit evidence; destructive cleanup is forbidden.
