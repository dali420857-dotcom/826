# 恢復操作手冊

## 進入安全停止

當出現未知錯誤、變更讀回不一致、裝置所有權不明或快取過期時：

1. 停止後續變更與自動重試。
2. 保留 `correlation_id`、`operation_id`、錯誤分類與讀回證據。
3. 將結果標記為 `warning` 或 `error`，不可回報為成功。
4. 確認最後一個有效快照與外部系統目前狀態。

## 提供者不可用

1. 只允許健康檢查與唯讀快取。
2. 快取超過 `config/storage.yaml` 的 freshness window 時，回傳 stale 狀態。
3. 不在提供者恢復前重放非冪等操作。
4. 恢復後重新驗證憑證、能力與讀回，再建立新的 correlation id。

## 變更讀回不一致

1. 凍結後續變更。
2. 保存請求、預期狀態、實際讀回與快照 ID。
3. 由人員明確選擇回滾或手動修復。
4. 回滾完成後重新執行健康檢查與 smoke test。

## 回滾前置條件

- snapshot 已建立且可讀
- 回滾能力已被批准
- idempotency key 已建立
- 回滾後有新鮮讀回
- audit event 已寫入
